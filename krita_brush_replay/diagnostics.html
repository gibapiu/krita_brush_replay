Diagnostics

The optional Diagnostics controls sit below Brush Replay and have their own status message.

  • Log to Krita output writes monitoring summaries with a [Brush Replay] prefix.
  • Collect diagnostic report retains recent monitoring records for export.
  • Turn both off to skip input and replay monitoring. Switches are available while idle.

Reporting pressure problems

  1. Enable report collection before testing.
  2. Record a few short strokes with light, heavy, and varying pen pressure, then stop.
  3. Run Replay and optionally Compare with current settings. Note which one differs.
  4. Press Export diagnostic report… and save the text file.
  5. Fill in the tester notes at the top, including tablet model, driver, reproduction steps, and expected versus actual pressure. Attach the file to your bug report.

The report includes a build marker and report ID, OS and Krita/Qt versions, relevant input settings, brush preset names, capture and replay pressure summaries, ignored mouse events, and capture or replay failures. It contains no canvas image or document contents.

Each docker retains at most 2,000 records in memory. Discarded history is marked in the report. Export soon after reproducing a problem; closing the docker discards its history. Disabling collection preserves records already collected.

The monitoring section records observation count, observation work time in milliseconds, and observation failures. Work time measures monitoring callbacks, excludes core processing, and does not include all wrapper or timer overhead.

For a run without monitoring wrappers or controls, the composition entry point supports compose_runtime(panel, application, diagnostics=False).
